MBW HRM — Backend API Development Schedule v2 (Testing & Feedback)

Timeframe: 5 months ≈ 20 weeks • Capacity: 24 days/month × 8h/day × 5 months = 960h

Scope & Services

  • Backend-only APIs aligned to BRS and your Sheets: SortedTables1 (tables) and APIList1 (endpoints).
  • Running services: api-gateway, auth, crm, hrm, notification, rabbitmq, redis, reporting.
  • Primary implementation: hr-admin-backend, crm-backend, reporting-backend; exposed via api-gateway-docker-micro-service under /api/v1.

Testing & Feedback Cadence

  • Build ~32h/week: implement endpoints, validation, RBAC, audit, pagination, error normalization, gateway mapping.
  • Test & Feedback ~8h/week: unit/integration tests, Postman/cURL demos, gateway verification, stakeholder demo, feedback triage.
  • Issue triage: categorize P0 (blockers, fix same week), P1 (high priority, fix within 1–2 weeks), P2 (noncritical, scheduled later).
  • Artifacts: Postman collection updates, test data seeds, changelog of endpoints, feedback log.

Demo & QA Method

  • Authenticate via auth, call gateway endpoints: GET/POST/PUT/DELETE /api/v1/{entity}.
  • Verify pagination (?page,size,sort,filter,q), RBAC (401/403), audit fields, error format {errorCode,message,details}.
  • Run integration tests against service containers; verify gateway CORS and route mapping.

Definition of Done (per API set)

Aspect Done Criteria
Endpoints GET/POST/PUT/DELETE implemented; validation; RBAC; audit; pagination; error normalization.
Tests Unit/integration tests pass; gateway smoke tests; regression updated.
Artifacts Postman/cURL scripts; seeds; changelog; feedback log.
Feedback Stakeholder demo done; P0 fixed same week; P1 scheduled; P2 backlog.

Risk & Buffers

  • Complex workflows (approvals, payroll rules) timeboxed to CRUD; advanced logic stubbed or deferred with clear contracts.
  • Weekly buffer ~4–8h for refactors from SortedTables1 changes or inter-service integration issues.
  • Gateway resiliency (timeouts/retries) tuned as needed; error observability added.
